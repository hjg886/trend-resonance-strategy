# 主引擎 OOS 不达标优化工作流（Track A → Track B 信号再设计）

## 何时使用

- 用户粘贴主引擎/策略 `IS x% / OOS y% — ≥3.5% ❌ 不达标，进行优化` 这类行。
- 任何趋势跟踪回测的 OOS 年化 < 默认门槛（3.5%），需要系统性优化而非临时拍脑袋调参。
- 适用对象：趋势共振策略主引擎、或结构类似（TRE 状态机 + 评分 + 现金管理组合）的回测工程。

## 核心决策树（关键：先 A 后 B，别死磕参数）

```
OOS < 3.5%?
 ├─ 先跑 Track A（参数调优，成本低）
 │    ├─ 趋势组件 OOS 转正且达标 → 落盘，结案
 │    └─ 趋势组件 OOS 仍为负（S1/S2 状态假突破持续亏损）
 │         └─ 诊断根因 = 信号结构设计问题（状态升级过松）
 │              └─ 转 Track B 信号再设计
 │                   └─ B1 主攻：TRE 状态升级收紧（S2 升级条件硬化）
 │                        ├─ 达标 → 落盘 + 回归 + 文档/报告刷新，结案
 │                        └─ 不达标 → B2（etf_score 重构）⚠️ 已证伪，见下节，勿重复立项
```

**铁律**：Track A 跑完若趋势组件 OOS 全为负，说明调参救不了——立刻转 Track B，不要扩大参数网格死磕。

## 验收标准（四关全过才算达标）

1. OOS ≥ 3.5%（破进阶闸门）
2. OOS > IS（样本外不能过拟合，外推性）
3. 最大回撤 ≤ 12%（风控底线）
4. 建仓频率 ≥ 6 笔/年（避免样本内偶然一两次交易撑起收益）

## Track A：参数调优（先执行，低成本的排除项）

靶向扫描 H1 / H2 / H6 三族参数，用 `sweep_trackA.py`（注意写 **v2 容错+resume 版**，避免会话压缩杀进程后只跑一半）：

- **H1** `BREADTH_MIN`：市场广度否决层阈值（基线 15）。
- **H2** `S1DERATE`（S1 突破置信率）、`VOL_GATE_B`（波动率闸门）。
- **H6** `VOL` 闸门：vol20<15 禁一切 / ≥20 禁 S1S2 / 15-20 正常。

判定：若 `etf_ann` 类趋势组件 OOS 仍为负（如基线 etf_ann OOS=-14.03%），Track A 失败 → 转 Track B。

## Track B1：TRE 状态升级收紧（信号再设计主攻）

根因诊断：S2 升级条件 `任一核心指数 ADX∈[15,20)` 过松 → 震荡市频繁假突破升级到 S2 触发建仓亏损。

改动三处（详见 `references/tre_b1_code.md`）：

1. **env 开关**（run_backtest.py 顶部读取，默认开）：
   - `BT_S2_MAJOR`（默认 `"1"`）→ S2 升级需“多数核心指数 ADX≥20”
   - `BT_S2_BREADTH_GATE`（默认 `"18.0"`）→ BREADTH 宽度门槛
2. **tre.py `raw_state` S2 兜底**：原“任一核心 ADX∈[15,20) 即 S2” → 改为“多数核心 ADX≥20 且 BREADTH≥gate 才判 S2，否则降为 S3”。
3. **`step_tre` 签名扩展**：新增 `s2_major_on / breadth / s2_breadth_gate` 参数；观察通道 `up_s2_cond` 同步收紧。

运行 B1 扫描脚本 `sweep_b1.py`（注意 `have()` 函数括号嵌套别写错，曾 SyntaxError）。最优格记为 `g18`（基线案例：IS 2.243% / OOS 3.862%）。

## Track B2：ETF 评分再设计 —— ⚠️ 已证伪结案（2026-08-26），勿重复立项

设想：`etf_score` 降动量权重（`MOM_SCALE` 缩放 RPS20/ret20）+ 新增估值分位（`NAV_PCTL_120`，见 `indicators.nav_pctl`）+ 低波维度，以降低动量暴露、提升稳健。

**实证结论：结构性失败，非参数问题。**

1. **网格全灭**：27 组（`est_w`×`vol_w`×`MOM_SCALE`）全 hardFAIL，OOS 仅 1.19–1.21%，ETF 建仓 0–1 笔。
2. **路径 A 复扫（"是否降动量过度"）证伪**：固定 B2 结构、只扫 `MOM_SCALE∈{0.5,0.7,0.85,1.0}` → 4 组 OOS **全部 1.213%**、ETF 建仓 **全 0 笔**、完全一致。
3. **根因（接线诊断实测）**：B2 新增的估值分位/低波权重过重，把 ETF 评分系统性压低——median ~50、p90 ~65，**即便 mom=1.0（满动量）也只有 3.8% 的 ETF-交易日 ≥70 门槛**；叠加 TRE 闸门（S4 全局禁建 / S1 禁 ETF）→ 实际建仓≈0 → 组合退化为"个股+纯现金管理"，与 mom 完全无关，故 4 组结果一致。
4. **对照**：V1（原 13 因子）评分 median 68.9 / #≥70 占 48.7%，OOS 3.862% PASS。
5. **处置**：不落地、不改主文档参数；`BT_B2_*` 仅保留实验位，默认关闭；主文档记 `v5.0-rc4` 结案行。唯一剩余方向"下调 est_w/vol_w"会退化回 V1 行为，无独立价值。

## 秒级接线诊断（长回测前必做，本轮最大方法论收获）

**症状**：多组参数扫描输出**完全一致**（同 IS/同 OOS/同建仓数）。

**错误反应**：直接怀疑"env 参数没传进去 / 接线 bug"，然后重跑 12 分钟 × N 组去验证。

**正确做法**：写一个**秒级诊断脚本**（复用回测真实数据管线 + 评分函数，不跑回测），在各参数值下直接算出**评分分布**（mean/median/p90/max/#≥门槛/占比）：

```python
# diag_b2a_wiring.py 骨架
import os, json
import run_backtest as rb
from scoring import etf_score            # 被测评分函数
panels = rb.build_panels(rb.load_all())  # 真实数据管线（含衍生列）
for mom in [0.5, 0.7, 0.85, 1.0]:
    os.environ["BT_B2_MOM_SCALE"] = str(mom)   # 关键：函数内实时读 env 才能生效
    scores = [etf_score(row) for row in 真实OOS窗口的所有ETF行]
    print(mom, mean, median, p90, max, sum(s>=70 for s in scores))
```

**判读法**：
- 参数**改变了**评分分布（如 mean 51.3→53.4、max 80.8→83.8）→ **接线正常**，"结果一致"是结论不是 bug，去查子通道建仓数是否为 0。
- 参数**完全不改变**评分 → 才是接线 bug（env 未读 / 传参丢失 / 缓存）。
- **先看子通道建仓数**：若目标通道建仓 0 笔，则该通道对结果无贡献，任何该通道内的参数都不会改变总体输出——这是"N 组一致"最常见的真因。

成本对比：诊断 ~10 秒 vs 复扫 12 分钟；诊断给的是**因果证据**，复扫只给现象。

## 经验教训 / 陷阱

- **Track A 翻不正趋势组件就转 Track B**：这是本工作流最大价值点——避免在无结构收益来源上浪费参数网格。
- **S2 升级过松是震荡市假突破根因**：硬化为“多数核心 ADX≥20 且 BREADTH≥gate”直接修复。
- **env 默认落盘**：**已验证达标**的开关默认开（如 `BT_S2_MAJOR=1`），确保“文档说达标”与“代码默认跑出来达标”一致，回归验证才成立。
- **⚠️ 实验开关默认值是头号地雷（本轮实伤）**：B2 开发期把 `BT_B2_ON` 默认写成 `"1"`，导致**不传 env 跑回测会静默产出已证伪结构的退化结果（OOS 1.21%）**，而真正的基线 3.86% 反而要显式 `BT_B2_ON=0` 才能复现——等于基线被污染且无报错。铁律：**未验证/已证伪的实验分支，默认值必须为 0（回退基线）；只有通过四关验收的改动才允许默认开。** 结案时第一件事就是把实验开关默认翻回 0，并用 smoke test 验证“默认走基线、显式开关走实验”两条路径。
- **同一评分函数双分支必做 smoke test**：`etf_score` 同一样本行在默认（V1）下 83.02、`BT_B2_ON=1`（B2）下 74.07 —— 用一行样本对比即可确认分支走向，比跑回测快 3 个数量级。
- **回归必须重跑默认参数对照扫描最优格**：只信扫描最优格会漏掉默认路径漂移。
- **工具通道故障规避**：多轮 Edit/Grep/Read 返回“expected string, but received undefined”属 GUI 层传输故障，用 Bash 直跑脚本规避。
- **用户命令用 Git Bash**：用户若把 `cd /e/...` + `grep` 类命令贴进 PowerShell 会报路径/命令不存在；AI 自身用 Git Bash 原生支持跑核验。
